# Change Log Runbook Rules

这个目录用于保存“大版本改动”的迁移说明，主要读者是之后要修改其他仓库的 Codex 或工程维护者。

## 维护规则

- 平时不用维护这个目录。日常小修、小参数、小排查结果仍然记录在 `readme.md`、`R2_MIGRATION_RUNBOOK.md` 和 `note.md` 里。
- 只有用户明确要求“把这次大改写成修改日志/迁移日志/给别的仓库参考”时，才新增一篇文档。
- 每篇文档要说明：
  - 当时遇到的问题和误区。
  - 讨论过程中排除过哪些方案。
  - 最终采用的设计。
  - 影响到的启动脚本、PlotJuggler、CAN、健康日志、TF、滤波和回退开关。
  - 迁移到其他仓库时哪些内容可以照搬，哪些必须按实机重新确认。
- 每篇大改日志的最后应增加“用户问题附录”，按时间顺序保存本次话题里用户单方面发给 Codex、且与该日志主题相关的中文问题或判断。这个附录的目的，是让另一个 Codex 能理解用户提出这些改动的真实背景和约束。
  - 以中文自然语言为主的问题、判断、要求、反驳和澄清，应尽量保留原意。
  - 重复发送的同一问题可以合并，并标注“用户多次追问/重复确认”。
  - 用户粘贴的大段代码、长报错、长日志、终端输出、二进制/地图/截图内容，不需要逐字放入附录；只写一句摘要、关键结论和必要路径即可。
  - 如果相关用户消息太多，导致附录会明显超过正文或难以阅读，应先向用户确认是否拆分为单独附录文件。
- 文档文件名使用英文、日期和主题，例如：
  - `2026-06-25-rc4-tf-tree-to-odom-pose-source.md`
- 不要把大体积运行日志、PCD 地图、截图资产放进这个目录。
- 如果一篇日志里提到某个版本号或 tag，需要尽量写明对应的 Git commit，方便回退。

## 与其他文档的关系

- `readme.md`：当前 Orange Pi 工程的使用说明和长期记忆。
- `R2_MIGRATION_RUNBOOK.md`：把当前工程流程迁移到 r2 的执行剧本。
- `note.md`：用户本地命令备忘和临时记录，通常不提交。
- `change_logs/`：少数大改的复盘和迁移参考，不要求每次提交都更新。
