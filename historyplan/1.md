# 让 `pose_from_odom` 在重定位模式走 FAST-LIO `/Odometry`

## Summary
只改 `pose_from_odom` 的输入来源：重定位模式下 `/robot/pose`、`/lidar/pose` 由 FAST-LIO 原始 `/Odometry` 转换得到，不再由 `/map_lidar/odom` 驱动。
不改 `MAP_LOCALIZER`、不改 `continuous_robot_pose`、不改 CANFD 默认 topic。

## Key Changes
- 修改 `autostart/pose_interface_relocalization.sh` 的 `odom)` 分支：
  - 新增 `INPUT_ODOM_TOPIC="${RC_ROBOT_POSE_INPUT_ODOM_TOPIC:-/Odometry}"`。
  - 把当前硬编码的 `input_odom_topic:=/map_lidar/odom` 改成 `input_odom_topic:="$INPUT_ODOM_TOPIC"`。
  - 日志从 `input=/map_lidar/odom` 改成打印真实输入，例如 `input=/Odometry`。
- 保留现有外参和业务坐标转换：
  - `/Odometry` 仍会经过 `body -> robot_base` 外参。
  - 输出仍是 `robot_origin` 坐标系下的 `/robot/pose` 和 `/lidar/pose`。
- 明确不改这些链路：
  - `map_localizer` 仍可继续发布 `/map_lidar/odom` 和 `/map_lidar/quality`。
  - `continuous_robot_pose` 仍按原逻辑使用 `/map_lidar/odom + /Odometry`。
  - CANFD 仍按当前配置使用 `/robot/pose_continuous`，除非你后面另说要一起切。

## Test Plan
- 静态检查：
  - `bash -n autostart/pose_interface_relocalization.sh`
  - `rg -n "input_odom_topic:=/map_lidar/odom|RC_ROBOT_POSE_INPUT_ODOM|input_odom_topic" autostart/pose_interface_relocalization.sh`
- 运行后验证：
  - 查看 `POSE_INTERFACE.log`，应显示 `input=/Odometry`。
  - `ros2 node info /lidar_pose_from_odom`，确认订阅里有 `/Odometry`。
  - `ros2 topic echo /robot/pose --once`，确认仍正常发布机器人业务坐标。
- 防误判：
  - 如果 `/map_lidar/odom` 还有订阅者，那可能是 `continuous_robot_pose` 或调试节点，不代表 `pose_from_odom` 还在吃它。

## Assumptions
- 你的目标只限于让 `pose_from_odom` 走 FAST-LIO 原始 `/Odometry`。
- 不把 CANFD 切到 `/robot/pose`。
- 不关闭 `MAP_LOCALIZER` 和 `/robot/pose_continuous`。
