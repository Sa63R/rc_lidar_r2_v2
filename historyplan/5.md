# `map_T_odom` 内部 0.95/0.05 平滑更新方案

## Summary
- 目标：不改多线程、不改输入队列、不改 scan/odom 同步逻辑，只改 `map_localizer` 内部接受 NDT 结果后的状态更新方式。
- 当前逻辑是：NDT 成功后 `map_T_odom = ndt_result`，下一帧 NDT 的 guess 直接使用这个完整结果。
- 新逻辑是：NDT 成功后不直接覆盖，而是用 `old_map_T_odom * 0.95 + ndt_result * 0.05` 的思想平滑更新，下一帧 NDT 的 guess 使用平滑后的 `map_T_odom`。
- 注意：这里平滑的对象不是 FAST-LIO 的 `/Odometry`，而是 `map` 到 `odom` 的修正量 `map_T_odom`。

## Core Logic
- 每轮 NDT 开始前：
  - `old_map_T_odom = 当前内部 map_T_odom`
  - `guess = old_map_T_odom`
  - NDT 用 `guess` 算出 `raw_result_map_T_odom`
- 如果 NDT 没通过原有质量判断：
  - 不更新 `map_T_odom`
  - 不发布新的重定位结果
- 如果 NDT 通过：
  - 不再执行 `map_T_odom = raw_result_map_T_odom`
  - 改成：
    ```text
    applied_map_T_odom = interpolate(old_map_T_odom, raw_result_map_T_odom, internal_alpha)
    map_T_odom = applied_map_T_odom
    ```
  - 默认：
    ```text
    internal_alpha = 0.05
    ```
- 下一帧 NDT 的 guess 使用 `applied_map_T_odom`，不是原始 NDT 结果。

## Implementation Details
- 不允许直接对 4x4 矩阵做线性加权：
  ```text
  old_matrix * 0.95 + new_matrix * 0.05
  ```
  这样会破坏旋转矩阵。
- 正确做法：
  - 平移部分：线性插值。
  - 旋转部分：四元数 slerp 插值。
- 推荐实现成一个独立函数：
  ```text
  interpolateTransform(old_T, new_T, alpha)
  ```
  行为：
  ```text
  old translation -> new translation: lerp(alpha)
  old rotation -> new rotation: quaternion slerp(alpha)
  ```
- 新增参数：
  ```text
  internal_map_to_odom_alpha: 0.05
  ```
- 为了避免初始化太慢：
  - 如果当前还没有有效 `map_T_odom`，第一次成功定位直接使用 NDT 结果。
  - 如果已有 `map_T_odom`，后续才使用 `0.05` 平滑。
- `/map_lidar/odom` 建议发布平滑后的 `applied_map_T_odom` 结果，而不是原始 `raw_result_map_T_odom`，这样对外发布值、内部状态、下一帧 guess 三者保持一致。

## Diagnostics
- 保留原有 fitness、converged、jump 等质量信息。
- 建议额外记录两个量，方便之后分析：
  ```text
  raw_map_to_odom_delta_xy
  raw_map_to_odom_delta_yaw_deg
  applied_map_to_odom_delta_xy
  applied_map_to_odom_delta_yaw_deg
  ```
- 这样可以看清楚：
  ```text
  NDT 原始结果想把 map_T_odom 拉多远
  实际内部状态只吸收了多少
  ```

## Expected Effect
- 单帧错误 NDT 结果不会 100% 污染下一帧 guess。
- 如果某次 NDT 错了 2m / 30deg，内部状态只会吸收约：
  ```text
  0.1m / 1.5deg
  ```
- 正常 FAST-LIO 漂移较慢时，`map_T_odom` 会缓慢跟随真实漂移。
- 这不是替代时间同步和旧帧拒绝的方案，而是额外的内部状态保险。

## Test Plan
- 静态检查：
  - 确认 NDT 成功后不再直接覆盖 `map_T_odom`。
  - 确认下一帧 NDT 的 `guess` 来自平滑后的 `map_T_odom`。
- 正常场地测试：
  - 对比修改前后 `map_T_odom_delta_xy/yaw`。
  - 确认重定位不会出现明显一帧大跳。
- 旋转压力测试：
  - 重点观察错误 fitness 被接受时，内部 `map_T_odom` 是否只发生小幅变化。
  - 确认 `/robot/pose_continuous` 不再被单次错误重定位明显拉飞。
- 长距离测试：
  - 确认 `internal_alpha = 0.05` 不会导致地图修正跟不上 FAST-LIO 慢漂移。
  - 如果跟随太慢，再把 alpha 提高到 `0.08` 或 `0.10`。

## Assumptions
- 这一版只做内部 `map_T_odom` 平滑，不改多线程、队列、同步逻辑。
- 默认 `internal_alpha = 0.05`。
- 对外 `/map_lidar/odom` 发布平滑后的结果，保持内部状态和外部输出一致。
- 原有 `pose_continuous` 的 `correction_alpha = 0.05` 暂时不改。
