# Point-LIO 三段并行对比链路计划

## Summary
- 目标改成和现有 FAST-LIO 完全对齐的三段链路：
  - FAST-LIO：纯 odom `/Odometry` → 重定位 `/map_lidar/odom` → 连续位姿 `/robot/pose_continuous`
  - Point-LIO：纯 odom `/pointlio/Odometry` → 重定位 `/pointlio/map_lidar/odom` → 连续位姿 `/pointlio/robot/pose_continuous`
- 第一阶段只做并行对比，不替换现有下游，不改 Point-LIO 算法源码。
- 地图使用你选定的 `maps/mid360_map_20260625_005422.pcd`，两条重定位链路共用同一张 PCD。

## Map Strategy
- 建图本质上还是用 FAST-LIO 当前能力：FAST-LIO 维护点云地图，并提供 `map_save` 服务保存 PCD。
- Point-LIO 第一阶段不单独建图，也不加载 prior PCD；它只做前端 odom，输出当前帧点云和 odom。
- 外置 `map_localizer` 才需要全局 PCD 地图；FAST-LIO 版和 Point-LIO 版 `map_localizer` 都读同一张 `005422` 地图，保证对比公平。
- 如果以后要重新建图：先只跑 Livox + FAST-LIO，走完整场地后调用 `ros2 service call /map_save std_srvs/srv/Trigger {}`，再把两条 localizer 的 `map_path` 同时切到新 PCD。

## Implementation Changes
- 启用 SMBU Point-LIO：
  - 删除 `src/point_lio_smbu/COLCON_IGNORE`。
  - 保留官方 ROS1 `src/Point-LIO` 继续忽略。

- 新增 Point-LIO 并行配置：
  - 新建 `src/point_lio_smbu/config/mid360_parallel.yaml`。
  - 输入改为绝对话题：`/livox/lidar`、`/livox/imu`。
  - 关闭 TF：`publish.tf_send_en: False`。
  - 关闭 Point-LIO PCD 保存和 prior map：`pcd_save_en: False`、`prior_pcd.enable: False`。

- 新增 Point-LIO 重定位配置：
  - 新建 `src/lidar_map_localization/config/map_localizer_pointlio.yaml`。
  - 输入：`/pointlio/cloud_registered` + `/pointlio/Odometry`。
  - 输出：`/pointlio/map_lidar/odom`、`/pointlio/map_lidar/pose`、`/pointlio/map_lidar/quality`。
  - `publish_tf: false`。
  - `map_path` 默认使用 `maps/mid360_map_20260625_005422.pcd`。

- 新增独立并行 launch：
  - 新建 `src/point_lio_smbu/launch/pointlio_parallel.launch.py`。
  - 启动 `/pointlio` namespace 下的 Point-LIO。
  - 将 Point-LIO 原始 `aft_mapped_to_init` 重映射成 `/pointlio/Odometry`。
  - 同时启动 `/pointlio/map_localizer`。
  - 同时启动 `/pointlio/continuous_robot_pose`，参数为：
    - `fast_odom_topic: /pointlio/Odometry`
    - `map_odom_topic: /pointlio/map_lidar/odom`
    - `quality_topic: /pointlio/map_lidar/quality`
    - `output_pose_topic: /pointlio/robot/pose_continuous`
    - `output_odom_topic: /pointlio/robot/odom_continuous`
    - `status_topic: /pointlio/robot/pose_continuous/status`

## Public Interfaces
- 现有 FAST-LIO 输出保持不变：
  - `/Odometry`
  - `/map_lidar/odom`
  - `/robot/pose_continuous`

- 新增 Point-LIO 对比输出：
  - `/pointlio/Odometry`
  - `/pointlio/map_lidar/odom`
  - `/pointlio/robot/pose_continuous`

- 第一阶段不输出到 `/robot/pose_continuous`，不影响 CAN、导航、现有控制链路。

## Test Plan
- 编译检查：
  - `colcon list --base-paths src | rg point_lio`
  - `colcon build --packages-select point_lio lidar_map_localization lidar_localization --symlink-install`

- 运行检查：
  - 先启动现有 FAST-LIO 链路。
  - 再启动 `ros2 launch point_lio pointlio_parallel.launch.py`。
  - 确认 Point-LIO 订阅 `/livox/lidar` 和 `/livox/imu`，没有误订阅 `/pointlio/livox/lidar`。
  - 确认三段 Point-LIO 输出都存在：`/pointlio/Odometry`、`/pointlio/map_lidar/odom`、`/pointlio/robot/pose_continuous`。

- 对比检查：
  - 同时录制 FAST-LIO 与 Point-LIO 三段 topic。
  - 重点比较 `/robot/pose_continuous` 和 `/pointlio/robot/pose_continuous` 的抖动、跳变、震动下稳定性。
  - 若 Point-LIO continuous 无输出，优先检查 `/pointlio/Odometry` 与 `/pointlio/map_lidar/odom` 时间戳是否能匹配。

## Assumptions
- 你说的 `pose_continues` 按当前代码实际 topic `/robot/pose_continuous` 对齐。
- 第一阶段不启用 Point-LIO TF，不把 Point-LIO 接入 CAN/导航主链路。
- 两条链路共用 `maps/mid360_map_20260625_005422.pcd`。
