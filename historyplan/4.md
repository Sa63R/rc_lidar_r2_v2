# Map Localizer 输入并行与时间同步改造方案

## Summary
- 目标：先按优先级 1/2/3 修掉重定位输入旧、scan/odom 时间戳错配、重复处理旧 scan 这三个问题。
- 不改变重定位算法本身，不替换 NDT/ICP，不改变现有 topic 名称和下游接口。
- 点云侧只保留“最新 scan”，不维护长点云队列；odom 侧维护时间队列，用 scan 时间戳去匹配最近 odom。
- 这一版重点是让系统“宁愿跳过一次重定位，也不要用旧数据/错配数据产生错误修正”。

## Key Changes
- 优先级 1：让输入 callback 和 NDT 并行
  - 将 `map_localizer` 节点从默认单线程 executor 改成 `MultiThreadedExecutor`，建议线程数默认 `3`。
  - scan subscription、odom subscription 放入输入 callback group。
  - localize timer 放入独立 callback group。
  - localize timer 必须防重入：如果上一轮 NDT 还没结束，下一轮 timer 直接跳过，避免多个 NDT 同时跑。
  - scan/odom callback 内只做必要的数据接收和缓存更新，所有 NDT、downsample、地图匹配都必须在 timer 逻辑里做。

- 优先级 2：scan 取最新，odom 按时间戳匹配
  - scan 侧保留一个 `latest_scan` 和 `latest_scan_stamp`，每次 scan callback 成功执行就覆盖。
  - odom 侧新增时间队列，按 `odom.header.stamp` 保存最近一段时间的 odom。
  - 新增参数：
    - `odom_buffer_duration_sec`，默认 `2.0`
    - `max_scan_odom_delta_sec`，默认 `0.05`
    - `max_scan_age_sec`，默认 `0.5`
  - 每次 NDT 开始前：
    - 拿当前最新 scan。
    - 用 scan stamp 在 odom 队列里找时间戳最近的 odom。
    - 如果没有 odom，跳过本轮。
    - 如果最近 odom 与 scan 的时间差超过 `max_scan_odom_delta_sec`，跳过本轮。
    - 如果 scan 本身 age 超过 `max_scan_age_sec`，跳过本轮。
    - 取出 scan/odom 快照后立刻释放锁，再执行 downsample 和 NDT。

- 优先级 3：禁止重复处理旧 scan，并输出诊断信息
  - 新增 `last_processed_scan_stamp`。
  - 如果当前 latest scan 的 stamp 等于上一轮已经处理过的 stamp，直接跳过，不再重复跑 NDT。
  - 原来的 timestamp mismatch 行为从“只报警但继续算”改成“发布质量信息并拒绝本轮”。
  - 质量 topic 保持兼容，已有字段不改变含义；如方便可追加诊断字段：
    - `scan_odom_delta_sec`
    - `scan_reused`
    - `reject_reason`
    - `odom_buffer_size`
  - 日志中明确区分拒绝原因：scan too old、no matching odom、scan/odom stamp mismatch、duplicate scan、NDT not converged、bad fitness。

## Behavior Details
- NDT 每轮只处理最新可同步 scan，不追历史点云，不补算旧帧。
- odom 队列在每次 odom callback 后裁剪，只保留最近 `odom_buffer_duration_sec` 的数据。
- scan callback 更新最新点云时，不因为 NDT 正在运行而被阻塞在 executor 层；互斥锁只保护缓存读写，不能覆盖 NDT 计算阶段。
- `publishLocalization` 使用的 odom 必须是与 scan stamp 匹配出来的 odom；输出 odom 的 header stamp 继续使用 scan stamp。
- 如果本轮被 age/sync/duplicate gate 拒绝，不更新内部 `map_T_odom`，不发布新的 `/map_lidar/odom`，只发布/记录质量状态。

## Test Plan
- 编译检查：
  - 构建包含 `map_localizer` 的包，确认 callback group、executor、deque 等改动无编译错误。
- 静态运行检查：
  - 启动现有 FAST-LIO + map_localizer。
  - 确认 scan/odom topic 名称不变，下游 `/map_lidar/odom`、quality topic 名称不变。
- 功能检查：
  - 旋转车辆或回放 bag，确认 NDT 运行时 scan/odom callback 仍能持续更新。
  - 检查日志中不再出现同一个 scan stamp 被连续多次 NDT 处理。
  - 检查 `scan_odom_delta_sec` 大于阈值时，本轮被拒绝而不是继续修正。
  - 检查 `scan_age_sec` 超过阈值时，本轮被拒绝而不是继续修正。
- 压力检查：
  - 在 OrangePi 上跑旋转压力测试。
  - 重点观察 `scan_age_sec`、`odom_age_sec`、`scan_odom_delta_sec`、`align_ms`。
  - 成功标准：即使 NDT 变慢，也不应接受明显旧数据或 scan/odom 错配数据生成的 map 修正。

## Assumptions
- 第一版只实现优先级 1/2/3，不同时调整 fitness、jump、overlap 等 NDT 接受门槛。
- 点云不做长队列，默认只保留最新一帧；如果实现上需要避免读写替换冲突，可以保留最新 2 帧，但不追历史帧。
- odom 队列默认保留 2 秒，足够覆盖 1 秒级偶发 NDT 慢处理。
- 时间同步阈值默认 50ms，scan 最大可用 age 默认 500ms；后续可以根据实测日志再收紧。
- 目标仓库的文件名可以不同，但改造对象就是负责“订阅 scan/odom、执行 NDT/ICP、发布 map_lidar odom/quality”的 map localizer 节点。
