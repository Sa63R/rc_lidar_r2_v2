# 视觉接收接口

主通道/vision/state，ROS 2类型std_msgs/msg/String，msg.data是一段JSON。
另有/vision/pose、/vision/odom供需要标准消息的程序使用；它们没有持续的失效心跳，
所以建议以/vision/state为可用性入口，不能只订阅pose并一直复用最后结果。

## 正常JSON示意（示意值，不是现场实测）

```json
{
  "schema_version": 1,
  "valid": true,
  "reason": "tracking_unverified_extrinsics",
  "reference_point": "corner",
  "position_unit": "m",
  "yaw_unit": "rad",
  "reference_id": "task3_start_示意编号",
  "data_source": "live",
  "output_components": ["x", "y", "yaw"],
  "z_valid": false,
  "physical_accuracy_verified": false,
  "data": {
    "stamp_ns": 1794473000000000000,
    "frame_id": "task3_start",
    "x": 0.1,
    "y": -0.2,
    "z": -0.33,
    "yaw": 1.5707963267948966
  }
}
```

z是内部兼容字段，不是已验证的地面高度。接口rad，UI显示度；+π/2等于逆时针90°。

## 接收规则

1. 检查schema_version=1、reference_point=corner、单位m/rad，实车使用data_source=live。
2. valid=true且data存在才读取；否则清除旧有效位置，按reason处理。
3. 检查data.stamp_ns的新鲜度：默认允许源年龄不超过0.5s、未来容差0.05s；接收心跳超过0.5s也弃用。
4. 保留原采样时间，不把旧坐标重新标为当前时间。跨机必须同步时钟。
5. 相同reference_id/frame_id/stamp_ns的重复心跳不是一份新的定位观测；用时间戳区分新采样。
6. reference_id或frame_id改变，清除旧场次轨迹/累计偏移，按新原点接收。
7. yaw在±π处可能换符号，角差使用环绕处理；有连续转角需求时在接收侧展开。

valid说明当前可用，不代表精度已验收。当前允许名义机械参数的工程试用，physical_accuracy_verified如实false。
不要为了显示绿色而改true。超时会发valid=false、data=null；停止发布程序后，接收端自己的超时检查仍需工作。

## 示例代码怎么用

```bash
bash bin/task3 receive
```

对应tools/vision_subscriber.py。它每秒打印最近接收的X/Y/yaw，持续检查有效性/时间、单位和起点变化，
不会把示例打印频率当定位频率。把相同检查逻辑接入视觉业务节点，在注释处增加视觉自己的角点→车心/相机换算。

它会显示physical_accuracy_verified=False，这是当前记录边界，不是没有输出。
如只需临时看消息，可在已source ROS的终端执行ros2 topic echo /vision/state std_msgs/msg/String --once，
该命令不代替业务程序的超时处理。

## 跨机如何分工

主机负责驱动、FAST-LIO、角点、接口持续发布；首次部署完成后视觉组可自行操作主机的一键入口。视觉电脑只运行订阅业务，不要启动第二套角点发布者。
两端ROS_DOMAIN_ID相同，ROS网络互通、时钟同步；网段和DDS配置由双方电脑实际环境决定。
先接ROS示例，再接视觉业务。真实跨机/视觉业务接入尚未执行，交付包的本机软件检查不代替该步骤。
如果视觉不用ROS，先确认目标协议（例如TCP或共享进程API），再开发适配，当前包没有冒称已支持全部方式。
