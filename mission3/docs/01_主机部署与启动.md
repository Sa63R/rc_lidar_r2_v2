# 主机部署与启动

主机指持续运行驱动、定位、角点计算的电脑。视觉可以同机订阅，也可以另一台电脑通过ROS网络接收。
目标主机环境尚未知，本包先按当前已验证的Ubuntu 24.04 / ROS 2 Jazzy交付源码；不要直接搬本机install目录。

## 1. 解压与环境报告

在目标电脑解压交付tar.gz，进入解压产生的task3_corner_vision_20261112_r1目录。

```bash
bash bin/task3 check --out host_environment.json
python3 tools/verify_release.py
```

第二条只核对交付源码清单。环境报告和校验成功都不代表硬件定位/精度已经验证。
若目标主机ROS/Ubuntu版本不同，先把报告交给维护者，不直接更改车体机械参数解决系统兼容问题。

## 2. 软件依赖与两种部署路径

基线需要ROS 2 Jazzy、colcon、系统Python的numpy/PyYAML/tkinter；上游还需要PCL、Eigen、
ROS的pcl_ros/pcl_conversions、Livox-SDK2共享库与头文件。主机已具备时不用重复安装。
依赖检查/安装按主机管理员的ROS环境进行，包不会在启动时自动sudo或安装系统软件。

### 路径A：主机已有正常的雷达栈

```bash
cp config/deploy.env.example config/deploy.env
```

编辑config/deploy.env，取消TASK3_BASE_SETUP那一行的注释，填写目标主机真实路径，示意：

```bash
TASK1_ROS_SETUP=/opt/ros/jazzy/setup.bash
TASK3_BASE_SETUP=/实际雷达工作空间/install/setup.bash
ROS_DOMAIN_ID=0
```

这是目标机路径，不能填开发者电脑的历史路径。然后：

```bash
bash bin/task3 build-app
```

### 路径B：需要部署包内驱动与FAST-LIO源码

vendor中包含从现场实际栈冻结的livox_ros_driver2与FAST_LIO源码及上游许可证。
先准备与ROS匹配的编译依赖；Livox-SDK2源码不在本包内，可按驱动README所链接的
[官方SDK2说明](https://github.com/Livox-SDK/Livox-SDK2)安装。驱动需要
/usr/local/lib/liblivox_lidar_sdk_shared.so及livox_lidar_api.h等头文件。

安装好依赖后，从交付目录执行：

```bash
bash bin/task3 build-stack
```

它在本目录upstream_ws构建上游，再构建应用，不覆盖目标机已有工作空间。
source路径运行时自动选择本目录upstream_ws/install/setup.bash；如果deploy.env设置了其他上游，则显式配置优先。
这条完整构建路径附有源码，尚未在未知目标机验证；当前已验证的是本机解压副本的应用构建与接口。

## 3. 雷达网络

当前车载MID-360为192.168.1.131；驱动JSON接收地址为主机192.168.1.5。
把连接雷达的目标机有线网口配置为192.168.1.5/24，无需默认网关；网卡名由目标机决定。
若主机地址需要改变，须同步改config/car_mid360_131.json的host_net_info各接收地址，不能只改环境变量。
视觉在另一台电脑时使用自己的唯一IP，不能也配置为192.168.1.5。该网段最好无其他主机占用同地址。

## 4. 日常启动：三个终端

每个终端先进入本交付目录。已有健康驱动/定位时跳过相应启动，不开第二份发布者。

终端1：

```bash
bash bin/task3 lidar
```

终端2：

```bash
bash bin/task3 fastlio
```

车保持静止，等IMU及局部地图初始化完成。

终端3（有桌面）：

```bash
bash bin/task3 ui
```

把指定车架角点的垂直投影对正式O，恢复规定初始朝向/场地轴，点击“建立起点并启动”，保持车不动，
程序用约2秒稳定样本建立本次task3_start。等待坐标出现和新起点编号，再允许移车。
图示轴与场地轴同向时，输出就是本次正式轴下的相对坐标；不能只摆O、不对初始朝向。

没有图形桌面，可将终端3替换为：

```bash
bash bin/task3 start
```

这是相同起点/接口逻辑的终端入口。初始点和方向仍需人实际摆正。
保存的历史起点不能在任意位置重启后直接复用；当前包不是任意位置上电的固定地图重定位系统。

## 5. 视觉接收

同机另开终端，进入交付目录：

```bash
bash bin/task3 receive
```

可加--seconds 10 --report receiver_report.json记录示例接收情况，报告路径必须不存在。
坐标会在尚无视觉业务程序时正常发布；接收示例只是另一个订阅者，不会拿走别人的消息。

跨机：接收电脑要有相容ROS 2环境，ROS_DOMAIN_ID一致，DDS网络允许发现/通信，时钟同步，
ROS_LOCALHOST_ONLY等配置不能限制到本机。网络隔离/多网卡时要按现场DDS实现配置。
接收端必须执行自己的超时检查；本机验证不能替代跨机验证。

## 6. 演示和停止

无雷达时可运行：

```bash
bash bin/task3 demo
```

合成演示仅在域93，UI明确标“离线演示”，不修改实车起点、不启动驱动或FAST-LIO。
它用于熟悉接收协议，不能测物理精度。无桌面可加--no-gui --seconds 8。

停止：先在UI停止接口并关闭窗口，再在FAST-LIO终端Ctrl+C，最后驱动终端Ctrl+C，之后才断电。
UI不会停止其他终端启动的雷达/定位。换起点会改变reference_id，视觉清空旧轨迹/累计偏移。

## 常见问题

| 现象 | 处理 |
|---|---|
| No module named rclpy或找不到ROS | 运行check，核对ROS安装及deploy.env；使用系统Python |
| 找不到fast_lio/livox_ros_driver2 | 配置已有上游路径或按路径B构建 |
| UI不能打开 | 主机可能无桌面/python3-tk，先使用start终端入口 |
| 起点无新鲜稳定窗口 | 检查源定位时效/链路及车是否静止，不修改时间戳冒充恢复 |
| valid=false | 按reason排查，弃用旧坐标，不仅看进程是否活着 |
| physical_accuracy_verified=false | 如实保留的精度状态，不是没有坐标；用户已选择先工程试用 |
| 转向出现几十厘米偏移 | 优先核对是否同一指定车架角点、安装方向和机械链，不能把它归零掩盖 |
